Chromebook OSK native input test

Pure HTML — no Flutter, no framework. On a Chromebook with the on-screen keyboard, focus each field, type one letter without touching Shift, and note (a) whether the first character is capital and (b) whether the suggestion strip appears. This isolates what the Chrome OS OSK actually honors.

A. Capitalization (watch the first typed letter)

A1 — autocapitalize="none" (spec value)

<input autocapitalize="none">

A2 — autocapitalize="off" (legacy synonym)

<input autocapitalize="off">

A3 — type="email" (email type usually disables autocap)

<input type="email" autocapitalize="none">

A4 — type="url"

<input type="url" autocapitalize="none">

A5 — inputmode="email"

<input inputmode="email" autocapitalize="none">
B. Suggestion strip (watch the bar above the keys)

B1 — autocomplete + spellcheck off

<input autocapitalize="none" autocomplete="off" spellcheck="false">

B2 — type="search" (search often hides predictions)

<input type="search" autocapitalize="none">

B3 — autocomplete="one-time-code"

<input autocapitalize="none" autocomplete="one-time-code">

B4 — type="email" + autocomplete off

<input type="email" autocomplete="off" spellcheck="false">
C. Kitchen sink (everything that might suppress both)

C1 — all suppressors combined

<input type="search" autocapitalize="none" autocomplete="off" spellcheck="false" autocorrect="off">

C2 — textarea variant

<textarea autocapitalize="none" autocomplete="off" spellcheck="false">

Tip: reload between fields if the OSK keeps its state. Record which case (if any) starts lowercase AND hides the suggestion strip.
